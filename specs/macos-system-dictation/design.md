# Design Document · macOS System Dictation

## Overview

The native host owns the global shortcut, foreground destination, and feedback. The existing authenticated helper pipe connects the host to Jard's single recorder and local Rumble2 Flash engine. React presents the tour and existing Settings surface.

## Architecture

`dictation_shortcut.h` handles shortcut state. `system_dictation.m` owns permissions, event tap, HUD, clipboard, preferences, and history on the Mac main thread. `mac_host.m` exposes permission and preference operations to the trusted Jard WebView and forwards global recorder operations to `mac_bridge.py` on its private pipe. Browser clients have only the existing workspace APIs. `SystemDictation` and `SystemDictationSettings` render onboarding and settings in the existing shell.

The capture ID isolates dictation from the other workflows. The finalized WAV goes through the native dictate endpoint. The engine performs inference with the configured Rumble2 Flash locale hints and reports its elapsed time alongside the transcript. Output cleanup is local. Jard removes temporary audio after success, error, or cancellation.

## Components and interfaces

- Use explicit permission buttons, status polling while on the permissions or practice step, and OS-owned microphone and Accessibility prompts.
- The host tracks focus changes following a request for Accessibility. After returning from System Settings it allows two seconds for a live grant, with a six-second fallback if Jard stayed active. An explicit repair resets the Accessibility service for the running bundle only, then repeats the native prompt and guide. An actual event tap failure while dictation is eligible enables restart guidance. Setup reopening uses the same app path, library environment, and recording guard as the existing desktop lifecycle path. The saved onboarding step is the resume point.
- Hex's `src/rune_ui/onboarding_kit/permissions.rs` presents the outstanding permission first, and `src/desktop/onboarding.rs` separates live readiness from the saved step. Jaro derives the active access card from the native microphone and Accessibility state, then displays model or listener readiness. A recovery card can temporarily cover saved practice or completion. The host keeps the guide and bundle-scoped repair available for those checkpoints, while the workspace resumes the same stage when ready.
- Hex's `ReturnFromSettings` and `src/rune_ui/macos_host.rs` give the frontmost System Settings window three seconds after a grant to finish authentication. Jaro uses the existing native Accessibility poll and consumes the return once. The desktop host rechecks the frontmost application, workspace visibility, session state, and capture and update guards immediately before ordering the existing window forward.
- The same reference host observes Screen Recording and audio-only grants. Jaro's AppKit host watches the latest explicit visit on one timer, and the two native permission controllers keep responsibility for detecting their own grants. Screen checks remain asynchronous and a previous probe cannot resolve a new visit. Mac audio checks use the tap permission. All three permission flows share the deadline and foreground decision.
- Keep the existing menu. Give Dictation its own General and History tabs in the workspace sidebar. Settings reuses the General controls.
- Consume matching shortcuts, their releases, and application re-paste events. An intent window lets a bare modifier remain available for ordinary chords. CoreGraphics and Accessibility use live permission checks.
- Offer vocabulary hints in the Rumble2 Flash prompt and a separate literal replacement list. For optional website rules, read the host from the focused field's nearest Accessibility web area. Fall back to the app rule when the browser does not expose it.
- Enumerate Core Audio microphone inputs by stable device UID and reuse the shipping microphone recorder. Selecting the system default can prefer a built-in input when Bluetooth would put a headset in its call-quality mode.
- Use an actual focusable practice field. The same native event and insertion pipeline feeds it.

## Data models

- Persist enabled state, onboarding step, shortcut code and modifiers, language hints, output preferences, sound, and HUD placement in native settings.
- Keep text-only history with UUID, timestamp, final and original text, and app name. Default to seven days. Practice text remains ephemeral.
- Keep the current destination, audio stage ID, word output, and clipboard generation on the host. The authenticated engine owns temporary audio and inference.

## Correctness properties

1. A press/release sequence has at most one capture owner. An accepted cancellation, permission loss, bridge exit, and app quit prevent later automatic insertion from that take.
2. Fresh dictation uses the active app and caret when the text is ready. Ordinary paste allows an unavailable or changed Accessibility caret and checks the foreground PID, permissions, and secure input before sending the full Command–V chord. Paste Last, practice, explicit typing, and meeting excerpts retain their captured destination checks. A newer clipboard copy survives asynchronous restoration.
3. Recording and personal note dictation retain their existing routes and event handling.
4. First-run status reflects real macOS permission state. The tour can resume and be replayed.
5. A take produces at most one history entry. Turning history off stops new entries while existing entries age out under the previous retention setting.

## Error handling

Keep the shortcut idle after a startup failure. Surface microphone and Accessibility recovery in setup. If paste is unsafe, preserve the finished text for recovery. If the engine is busy, show the existing recorder's reason. Trigger keyboard and microphone access only through the feature enablement and setup flow.

### Clipboard format preservation

Hex's `src/paste.rs` inspects native pasteboard flavor flags before reading clipboard data. Jard applies the same check in `system_dictation.m` on the main-thread clipboard transaction shared by dictation, meeting paste, and annotation paste. It leaves out macOS translations when an item has an original format because the system can generate those alternatives from the restored original. It retains the data and writable flags of the remaining formats within the existing 16 MiB budget. An unreadable required format leaves the clipboard untouched. Clipboard revision checks guard both the paste and restoration. The temporary transcript also carries the auto-generated marker used by clipboard managers.

## Testing strategy

Test the shortcut reducer with deterministic timestamps. Exercise recorder ownership, cleanup, and Rumble2 Flash with the existing bridge fixture and a disposable audio take. Compile the host and build an Apple silicon application bundle. Use an isolated app identity to exercise first-run and settings. Physical Mac verification covers the native prompts, speech into a practice field and into another app, clipboard restoration, and window-closed behavior.

## Parity implementation

Hex's `src/audio/recording_environment.rs` and `src/capture_host.rs` give dictation and Annotate separate ownership of playback effects, with idle-sleep prevention scoped to intentional dictation. Jaro's `JardRecordingEnvironment` serializes both owners, holds the strongest volume reduction, and pauses players until the last Pause media owner releases them. It saves the controlled channels on the original output device, compares subsequent readings against its own writes, and releases an effect when an outside volume change takes ownership. Lower audio uses a 120 ms attack and one-second recovery after the last owner leaves. An annotation starts its effect only when the native recorder enters the recording phase and releases it before import. Warm dictation accepts a per-take pre-roll flag and drops standby packets when dictation playback is suppressed.

Pause media uses a separate `JardDictationMedia` queue so an unresponsive player cannot delay capture or its cues. The settings button can request macOS Automation consent for open Music, Spotify, or VLC. Capture's Apple Events target only those running processes and suppress consent prompts. Jard keeps an in-memory resume record only for output it successfully paused, using the same process, track identity and paused position. It discards a record on restart, playback changes, or unavailable state. VLC's play command toggles playback, so the host verifies state before using it in either direction.

- **Microphone lifetime.** Hex distinguishes warm, cold, shortcut finish, device loss, and away states. Jard's persistent mic-only helper keeps up to 1.5 seconds of converted samples in memory for release-tail handoffs. Ordinary warm takes use up to 450 ms of standby pre-roll. The bridge arbitrates the worker against cold, note, and meeting capture. The host reconciles the preference with macOS session and power notifications.
- **Lock and sleep.** The native dictation controller observes both Workspace power and session transitions and distributed screen lock events. It reads Core Graphics display and lock properties before the first refresh. Each reason independently holds the existing listener and warm-worker gate. The same state rejects stale delivery and browser context reads.
- **Shortcut finish.** Hex's `src/dictation.rs` and `src/transcription/pause_segmenter.rs` follow recently captured audio to preserve the end of a word. Jard maps the finishing event to a frame in the warm or cold recorder. It tracks DC-removed levels in 20 ms windows, using an adaptive noise floor and a 12 dB speech margin. The WAV ends at 200 ms unless five speech frames, tolerating gaps of up to two frames, lead into the cutoff. A longer tail ends at eight consecutive quiet frames or 600 ms. The recorder can wait up to an extra 100 ms for delayed microphone packets. Jard plays the stop cue after the WAV has closed.
- **Press during the release tail.** Hex's `src/dictation/audio.rs` finishes the prior clip before starting the next and passes the original press to `start_hotkey_at`. Its `src/dictation.rs` extends sample retention from the oldest pending input and includes 450 ms before the press when playback is unchanged. Jard snapshots the foreground destination and take preferences at the press. Its warm helper keeps a fixed window sized for pre-roll, the release-tail cap, and callback delivery. The next warm take uses the press and release timestamps even when both events arrive before the previous take closes. Cold takes open if the next gesture is still active when the recorder becomes available. The same live-audio rule applies when the next take suppresses playback, so its audio starts under the requested playback policy.
- **Microphone interruption.** Hex's `src/dictation/audio.rs` saves the audio delivered before a genuine loss and copies an eligible transcript. Jard keeps the last mic frame on the recorder's timeline and distinguishes stream loss from a gap over 250 ms or an unrelated recording error. The helper reports the failure time, the captured-through timestamp, and whether the prefix contains live samples beyond warm standby. The host uses the failure time for intention and the last audio time as evidence for a stall discovered later. The surviving take uses the ordinary or raw transcription path and is copied only while the clipboard revision and secure-input state allow it. History and Paste Last preserve the text for recovery. A duplicate notification for a queued stage leaves that stage with its current job, and a late orphan is released.
- **Cold microphone reopen.** Hex sends a cold capture that fails before the hold threshold back to its pending state. Jard starts one replacement recorder with a fresh stage identity under the existing gesture. The destination, model and input preferences, playback effects, and start cue stay scoped to the logical take. The old process and its stage can retire independently. Finish carries the original physical release timestamp even if the replacement launch has yet to acknowledge. The cold recorder's opening timestamp prevents a release before readiness from admitting tail audio.
- **Cold input selection.** Hex's `src/audio.rs` retries a listed input twice in 100 ms steps before using the default. Jard enables that policy for on-demand system dictation. It uses the existing Bluetooth-aware default resolver and attempts the saved selection again on the next take. A stop or physical release during opening fences each pending attempt and the final WAV creation. The native bridge reports a successful fallback device or cleans up an abandoned opening before notifying the host.
- **Warm stream recovery.** Hex's `src/audio.rs` and `src/audio/recovery.rs` distinguish a failed open from a stream that opens but stalls before proving delivery. Jaro's persistent warm helper retains those two retry ceilings and resets the stream budget when eight seconds of packets arrive without a four-second gap. It retires the failed engine and drops its pre-roll before waiting. Capture starts and a resolved input change can interrupt that wait. The worker tracks audio delivery with monotonic timestamps and a stream generation, so a callback from a retired tap cannot prove a replacement or enter its pre-roll. Microphone permission and the bridge's existing ownership rules still govern admission.
- **Warm fallback input.** Hex's `open_configured_input` uses the default when the saved microphone is listed but cannot open. The working stream stays installed until its replacement is ready, and a listed device is retried from idle. Jaro resolves a saved and a default input separately, then retries the saved input once per eligible standby tick with an independent 250 ms to five-second backoff. Successful replacement swaps the sample generation before stopping the fallback and clears pre-roll from the old input. A take pins its input through the release tail and reports when it uses the default.
- **Closed-lid input.** Hex's `audio/lid.rs` reads the IOKit power root's clamshell property. Its `audio/transport.rs` distinguishes the headphone jack from the internal microphone by UID and input data source. Jaro shares that routing policy across the warm helper and native dictation opens. The warm worker's existing maintenance tick observes route changes during standby. Cold, warm, and SDK dictation pin the input for the take. When the lid disables that input, the recorder keeps the existing recovery boundary. Basic recording and Meetings retain their existing input policies.
- **Live microphone choices.** The Core Audio property listeners in Hex's `src/audio.rs` and the clamshell notification in `src/audio/lid.rs` invalidate a device snapshot. Jaro also re-registers Core Audio listeners after a service restart and coalesces simultaneous input notifications in AppKit. The visible Dictation pane asks the recorder helper only for device metadata. It serializes refreshes and ignores a reply once a newer notification arrives. The same route resolver supplies the current default and Bluetooth fallback. Closing the lid disables the internal input's option while preserving the user's existing selection. Device reads do not open an audio stream or touch the session library.
- **Opening a warm input.** Hex's `RecoveringAudioInput::start_replacement` moves a hardware open to a worker and gives its result the route revision. Jaro moves its AVAudioEngine open to a serial background queue and returns the result with its device and route. The capture loop can use a working fallback or hold a start until a valid result arrives. Stop, Cancel, and earlier shortcut releases abandon the pending take. The worker releases a candidate that cannot be adopted. Only a committed input generation can deliver audio.
- **Warm input status.** Hex's listener view reports the current warning before the last-take failure, and its audio recovery deduplicates an outage. Jaro gives the bridge one reader for a warm worker and routes the active take's events to the owning recorder. Availability events can arrive during standby without attaching to a take. The native controller accepts events only for its latest warm request. The workspace shows the device notice without changing the listener's enable state or the durable last-take result.
- **Digital silence.** The warm microphone tracks the first nonzero live frame so audio after release cannot hide digital silence before it. A finished zero take arms one reopen for the same device UID. Once the old engine has stopped, the helper checks whether the device is running elsewhere, selects an advertised alternate nominal rate, primes and closes a throwaway input with discarded samples, and restores the original rate before opening normally. That one-shot request is consumed even if the device is busy, changed, or failed to renegotiate. Plain stream failures reopen without changing the nominal rate.
- **Independent takes.** Hex's dictation service recognizes microphone ownership and processing jobs as separate states. Jard detaches each finalized stage and snapshots the destination and preferences. A FIFO of completed jobs waits for active capture and clipboard delivery, while one Rumble2 Flash inference lock continues to bound model concurrency. The recording's Cancel shortcut leaves accepted output queued. The explicit CLI cancel command can also cancel a pending job.
- **Near-silent audio.** The native dictate endpoint scans finalized 48 kHz microphone WAVs before decoding, using bounded reads inside the existing audio-priority scope. It applies the level policy in Hex's `src/dictation.rs`: DC-removed 30 ms windows, a fixed −50 dBFS trigger, and a relative trigger based on the clip's 10th-percentile floor plus 12 dB with a −66 dBFS minimum. The relative trigger needs six qualifying windows and can bridge one quiet window. When neither trigger passes, the bridge returns the existing empty result and cleans up the stage. The host keeps Paste Last and History available.
- **Louder audio without speech.** Hex uses a separate speech detector. Jard uses the existing Rumble2 Flash encoder and its installed CTC alignment head before autoregressive generation. It rejects a block only when blank exceeds every token by at least two logits on every real frame. Short blocks are padded to reuse a fixed projection shape, and padding is excluded from the decision. The recorder's release frame bounds both the WAV level check and the acoustic eligibility check. If a block crosses that frame, the acoustic screen encodes the prefix separately so its features depend only on that audio. An admitted block is then transcribed with its complete ending. For other blocks the decoder can reuse embeddings from the screen, and if the optional head or screening path fails, it receives the original input.
- **App-specific insertion.** Hex's `paste.rs` and `keyboard.rs` type into Microsoft's remote desktop clients and apps with the Chromium 155–156 clipboard race. For fresh paste-mode dictation, Jard selects that strategy using the current foreground app and captures its caret before typing. Typed insertion uses bounded Unicode events and Shift–Return. A remote client receives the physical key and Shift edges from the current layout, spaced by a main-run-loop timer. Each character checks the destination, secure input, and intervening user input, while allowing the caret to advance as Jard types. Text stays in history when output stops. The ordinary paste path verifies clipboard ownership and destination again before sending V.
- **Paste keyboard layout.** Hex's `src/keyboard.rs` prioritizes the Command layer, the plain layer, and the ASCII-capable layout for Command–V. Jard queries Text Input Sources on the main thread at delivery, so the shared dictation, meeting, and annotation paste path follows input source changes. ANSI V is the last fallback when layout data has no match. The native host rechecks clipboard ownership after resolving the key.
- **Letter shortcuts across layouts.** Hex resolves the letter printed on the keycap and defers rebinding active shortcut machines. Jard derives the letter from the existing saved label, and watches macOS's selected-input-source notification. The main thread publishes the plain and Command key maps after preserving any active capture and consumed shortcut releases. Non-letter keys and unresolved codes use the persisted binding. The event tap, conflict checks, and temporary Carbon hotkeys use the same lookup.
- **Continuing a dictation.** Hex's `src/continuation.rs` ties sentence-aware joins to an input revision. Jard applies that policy at delivery for dictation, raw dictation and Paste Last, using the same revision, app and focused element, and checking the predicted caret when the app exposes a selection. Queued takes can advance from the selection they captured before the previous paste only when Accessibility confirms its new position. Copy-only and standalone meeting excerpts end the sequence. Formatting for insertion does not change History or Paste Last's stored text.
- **Secure-input shortcut recovery.** Hex's `suppression/secure_input.rs` registers compatible key chords through Carbon only while Secure Event Input is active. Jard uses the same temporary registration for Annotate, Paste Last, and the meeting paste chord. Annotation edges go to the existing gesture reducer, and a departing registration cancels a held gesture. Protected paste shortcuts report that input is secure and keep the saved text and clipboard available. Carbon does not carry Fn, mouse, or sided modifier distinctions. Entering secure input ends an active take without extending its recording tail, disarms the original insertion, and releases the warm microphone after capture finishes. macOS returns ordinary shortcut handling to the shared event tap when secure input ends.
- **Cancel a recording.** Hex's `src/suppression/hotkey.rs` arms the configurable Cancel shortcut during Tap mode recordings. Jard stores it alongside the other bindings and uses the original key code to balance a swallowed down event through repeats, drags, and release. The recording reducer tracks when the press began for Hold mode's 300 ms Escape threshold. Locked double-tap takes and accepted output pass Escape through. Annotation gets the first chance to handle a new Escape press.
- **Chords and lost releases.** The session tap owns shortcut edges. A listen-only HID tap supplies chord evidence when macOS allows it, including keys consumed by system or app shortcuts before the session tap. Jard compares event timestamps to allow for different delivery orders and keeps only the last eight evidence timestamps in memory. Both paths use the same rules for early chords, ordinary keys during a modifier-only hold, and the Return and keypad Enter exception. Physical-state sampling clears a missed release only while idle or locked. A lock still needs a fresh press to finish.
- **Stale Quartz state.** Hex's `src/suppression/tap.rs` corroborates a session key with HID state. Jard uses that rule for modifier-only starts and samples the full keyboard and mouse before releasing stale bookkeeping. Like `src/suppression/hotkey.rs`, Jard can admit a fresh modifier press when a key still reports down in both sources if modifiers returned to neutral after the key went down and the key has sent no repeat for five seconds. Only an observed Fn release can excuse stale navigation metadata. A recovery timestamp fences older events in both taps while allowing same-timestamp chord evidence.
- **Provisional holds and double-tap.** Like Hex's `src/suppression/hotkey.rs`, Jard measures a hold from the event timestamp and decides double-tap only on the second release, within 300 ms of the first release. Keyed holds open on press. Modifier-only holds keep the existing 175 ms delay and warmed audio retains its pre-roll. A release before 300 ms cancels the provisional audio without a release tail or a history entry. When a short take is still closing, the native controller keeps the next gesture separate and opens its recorder after the old capture lease is released. A keyed chord ends when a required modifier or its key goes up, and the consumed key's release stays balanced.
- **Shortcut mode chooser.** Hex's `src/rune_ui/explainer.rs` demonstrates shortcut presses and recording intervals side by side. Jaro illustrates the same four gestures with two labeled lanes and a moving playhead. The diagram shows accepted takes and uses a static frame with Reduce Motion. The chooser reads the current binding and saves the existing native mode, preserving Jaro's modifier-only double-tap support.
- **Shortcut side.** For a lone paired modifier, the native shortcut keeps its virtual key code and stores whether Either was selected. Existing saved codes stay fixed to their recorded side. The event tap uses the modifier family's transition from neutral to down to detect a fresh press. For Either, releasing one of two held keys leaves the gesture active. For a fixed side, releasing the chosen key ends the gesture even if its counterpart is held, and an early press of the counterpart discards the candidate. The settings row is available whenever the recorded shortcut supports sides.
- **Remapped side evidence.** Hex's `src/suppression/physical_keys.rs` reads live modifier state below the macOS keyboard remapping filter. Jard opens a nonseizing HID manager off the UI thread when the existing Input Monitoring check passes. The manager keeps the union of held Caps Lock and sided-modifier usages across keyboards and clears a disconnected device's state. While Caps Lock is physically held, Jard drops a Quartz side bit unsupported by the raw state and keeps the general modifier flag. The same check applies to matching, recording, and modifier claims. The ordinary listener continues while raw state is unavailable. As in Hex, a raw callback that arrives after its Quartz event can leave that edge ambiguous.
- **Globe and layout events.** Hex treats the Globe key event sent alongside the Fn flag as part of an Fn gesture. Jard excludes that companion from physical chord evidence, active chord cancellation, and insertion-target invalidation while letting the foreground app receive it. The recorder uses Carbon's current layout translation with dead-key processing disabled when AppKit has no printable label.
- **Optional shortcut recording.** Hex's `src/rune_ui/settings.rs` uses plain Delete to turn optional bindings off and uses the usual conflict checks for Reset. Jard consumes the matched press and release, persists the off state for Paste Last and raw dictation, and shows the recorder again on a reset conflict. A modified Delete remains available as a binding. The Paste Last row exposes its default when off.
- **Command output.** Hex's `docs/cli.md` defines core raw start and printing stop, with printing start in Labs. Jard sends raw start and printing stop as distinct authenticated actions so a host from an earlier build can reject them. Raw starts use the primary shortcut to finish and the raw job path for processing. Printing stop attaches one bounded reply to the active capture, then hands the reply to its job as soon as the audio closes. The job uses the shared final text and output processing. It resolves the reply independently of the insertion queue and records its own History kind, which Paste Last skips on delivery and reopen.
- **Modifier-only chords.** The shortcut recorder saves the largest set of modifiers held together and commits when they are released. A multi-modifier chord stores its required families and the families that require both keys. The event tap needs an exact set to start, uses per-side timestamps for the 80 ms condition, and releases the gesture when a required part lifts. Both the primary and raw binding use the existing Hold and Tap reducer. An exact chord can replace an early provisional single-modifier prefix. A lone modifier retains its existing side behavior.
- **Global modifier-tap conflicts.** Like Hex's `src/suppression/hotkey.rs`, Jard emits a marked press and release of an unused virtual key at the HID stage once per owned modifier gesture. The deadline is 300 ms for a Hold, 40 ms for Tap, and immediate for a press that finishes a lock. A fresh hardware flag check verifies the binding. The session listener ignores the pair and an annotated-session tap consumes its marker before the foreground app. Jard schedules the pair only while its filter is available and skips it after a release, interruption, or unrelated chord. Fn and keyed bindings use their existing paths.
- **Output profiles.** Hex's `dictation/processor.rs`, `dictation/spoken_formatting.rs`, `dictation/spoken_symbols.rs`, and `rune_ui` output controls distinguish ordered operations and destination overrides. Jard preserves existing preferences as defaults and introduces an optional ordered pipeline with a local preview. Text transformations and explicit scripts are independent of the speech model.
- **Additive controls.** Hex's General, History, and Labs map to sections in Jard's existing Settings. Additional bindings are matched through the same event tap. The default application menu stays compact. Developer control and annotations have separate acceptance checks.

The output editor saves structured profiles in the existing `outputProfiles` preference. `dictation_output.py` reads the structured form and the earlier line format. It validates both, preserves first-match priority within each scope, and prefers website over application over default. The bridge resolves from the native take's destination snapshot before transcription, merges scoped and shared hints, and uses the same resolved settings for local rewrite. A profile can supply hints without a cleanup step. If a saved document becomes invalid, Jard still transcribes and reports a profile warning. The preview uses the same resolver, while validation loads the definition without running any steps.

Hex's `src/dictation/processor.rs` preserves corrected text if rewriting fails, and its transformation chain discards partial results if a transformation fails. Jard gives each rewrite and each adjacent group of transformations a text checkpoint, preserving the user's step order. The bridge returns the recovered text with a warning, so the host can deliver it through the ordinary focus and clipboard guards. The authenticated Qwen endpoint applies the selected deadline to waiting for the model, startup, prompt fitting, and generation. Newly created profiles default to 30 seconds. Existing profiles keep their 60-second limit until edited.

Like Hex's `src/dictation/text_replacements.rs`, scoped replacements operate on the text from the shared replacement pass. The scoped pass prefers the longest overlapping phrase and applies each rule against the original input to that pass. It supports writing systems that do not separate words with spaces and tidies spacing and punctuation when deleting a phrase. The existing Apply word replacements step determines when both passes run. A profile with its own rules and no explicit replacement step applies them before the ordered steps. Existing profiles keep their shared replacement behavior. Each rewrite checks its input for numbers-only speech, including signed or punctuated digits and English cardinal numbers, before requesting Qwen.

Hex implements three native text steps in `src/personal_commands.rs`. Jard uses their saved identifiers in the existing ordered pipeline and editor. The steps work in preview and completed dictation without starting a model or an executable. They retain the existing adjacent-step rollback and common final output handling.

Hex reduces site selectors to canonical hosts in `src/dictation/modes.rs` and recognizes the Finder bundle name in `src/dictation/context.rs`. Jard normalizes both profile selectors and captured or sample website contexts, preserving the saved definition and first-match ordering. Its native host supplies the Finder name from the captured destination's bundle alongside the running app name and bundle ID. Website matching uses the existing Accessibility host read and adds no browser permissions.


Hex's `src/recognition/context_watch.rs` bounds its context handoff to one second and drops a missing page. Jard pins the output application at the accepted stop edge, including a queued warm take. If a profile uses a website, a bounded worker reads only the focused external AX page for that PID. An intervening input revision, focus switch, secure input, or expired deadline drops the page. This profile snapshot is independent of the press-time paste identity and delivery rules. The queue preserves job admission order while the page resolves and discards an unsubmitted stage on cancellation.


For browsers with scripting dictionaries, `jard_dictation_browser.m` requests the front window's current tab in Safari-style dictionaries or active tab in Chromium-style dictionaries. It uses a PID-addressed, read-only Apple event with interaction and consent prompts suppressed. Jard discards everything except the HTTP or HTTPS host and falls back to its bounded Accessibility reader. The browser and focus checks at release continue to fence both paths. An explicit browser-access button in Dictation can request consent for the most recently used supported browser while Jard is idle.


## Restart to Update

Hex stages and verifies the archive in its app's containing volume, offers a small sidebar control when the stage is ready, and uses an atomic directory exchange. Jard uses the same lifecycle with its signed feed and Apple bundle designated requirement. A user-private stage sits beside the bundle. Restart rechecks capture and the shared engine, verifies the selected stage again, and exchanges it using `renamex_np`. The replacement starts from the same path. A restart waits for recording, other connected clients, and local inference to finish. A read-only copy opens the release page.

Hex's `src/updater.rs` performs a final manifest request on every restart and bounds the entire request, including the response body, at fifteen seconds. Jard uses a separate feed session and archive session so the feed deadline can also bound a stalled response that still sends bytes. It bypasses the local response cache for feed requests.
