# Windows and Linux desktop support

**First work item** · Run Jaro’s local speech engine on Windows and Linux

**Status** · File transcription, the Native SDK workspace, and microphone and computer-audio recording passed independently and together in a Linux x64 VM. The Windows x64 host and its capture and dictation helpers cross-compile. All three recording modes captured separately routed signals under Wine. Left Alt dictation carried a WASAPI recording through Rumble2 Flash on the Linux host and inserted the transcript in a Win32 editor under Wine. Native Windows and Ubuntu desktop validation is pending.

**Initial targets** · Windows 11 x64 and Ubuntu 24.04 LTS x86-64, with GNOME Wayland and X11 verified separately for desktop features. Expand the supported distributions, compositors, and architectures after testing those combinations.

## Requirements

- **R1 · Same local models.** Run Rumble2 Flash and its CTC alignment model for transcription, Nemotron for speaker diarization, and the pinned Qwen model for local text generation. Install and verify model assets before use. Process recordings and inference locally by default.
- **R2 · Portable engine contract.** Keep the existing session format, CLI, and SDK behavior. Use per-user storage and a loopback engine with process identity and request authentication. The separate Apple Silicon build must continue to pass its existing checks.
- **R3 · Supported desktop workflows.** Verify recording and import, sessions with notes and the timestamped overview, searchable dictation history, dictation into a focused app, meetings with speaker labels, annotated screen capture, exports, agent handoffs, SDK access, and updates. Surface any platform-specific capability limit next to the affected action.
- **R4 · Install and recover.** Install for the current user through a verified release artifact. Preserve sessions, preferences, model data, and permissions as the platform permits during upgrade, rollback, and uninstall.

### First-run model setup (R1, R3, R4)

- A new desktop installation shall show the size of the pinned local model set and offer to download it from the Home screen.
- After the user agrees, Jaro shall show progress and open its normal recording controls once Rumble2 Flash is loaded. An existing working speech installation shall open directly.
- After an interruption, the user shall be able to retry with the files already downloaded. Repeated requests shall share the same install.
- Only the owned desktop workspace shall be allowed to start model setup.

### Linux dictation shortcut modes (R2, R3)

- X11 and Wayland sessions with a connected shortcut portal shall offer Hold, Tap, Hold or double-tap, and Double-tap only. Existing libraries shall start in Tap mode until the user chooses a mode.
- A hold shall finish on release with a short audio tail. A release before the recorder opens shall discard the take. A deliberate double-tap shall start or lock hands-free dictation, and a fresh press shall finish it.
- Keyboard repeats shall leave the current take running. A most-recent-take recovery shortcut and the existing consent and insertion rules shall still apply. Desktop commands shall keep their explicit start, stop, and toggle behavior.

### Restore global shortcuts (R2, R3, R4)

- An owned workspace shall remember an explicit choice to enable or disable the global shortcut. A fresh or migrated library shall start with the listener off.
- Restore an enabled listener after speech setup, including when a restart or update opens the library again. Report conflicts in Dictation and let the user retry or turn off restoration.
- Wayland shall check for Jaro’s existing compositor assignment before restoring the listener. If the assignment is missing, require an explicit Enable action.
- Wayland automatic paste shall have separate consent from the global shortcut. Restore only a previously granted keyboard and clipboard session and accept the desktop’s decision on every start. Remove the locally saved grant when automatic paste is disabled or the desktop closes that active session. An older desktop shall still support temporary access where it offers both capabilities.

### Vocabulary and word replacements (R1–R3)

- The same vocabulary editor shall be available on Windows and Linux. Rumble2 Flash shall receive up to 32 preferred terms, each with optional whole-phrase alternate spellings.
- Save vocabulary and word replacement rules per library and snapshot them at the start of a system dictation. Apply deterministic corrections before paste and history. Keep original audio in History. Empty settings shall use the existing output path.
- Reject malformed rules and stale vocabulary edits. Leave normal recordings, meeting audio, and SDK output on their existing paths.
- Offer ordered output profiles for system dictation with a default for all apps and application matching on Windows and X11. Use the default on Wayland. Run Qwen only when a profile explicitly requests it. Preserve the text before the rewrite when generation fails or changes a number.

### Floating dictation indicator (R2, R3)

- Show a text-free microphone meter during system dictation. Distinguish active capture from pending output and hide the indicator after paste, cancellation, or failure.
- Use a non-activating, click-through surface. Offer Top, Bottom, and Off per library. The indicator shall never be required for dictation or paste.

### Dictation sound feedback (R2, R3)

- Share Jaro’s bundled dictation cue sets. Save style, enabled state, and volume per library. Offer an audition using the same output device and gain as live feedback.
- Start cues require an open microphone and a deliberate gesture. Play stop and completion cues after the recorder closes. Leave transcription and paste available if playback fails.

### Cancel a dictation (R2, R3)

- Discard the active take from the workspace or an available desktop shortcut before the transcript is committed. Preserve the active app’s text, clipboard, and previous dictation history.
- On X11, give Escape to Jaro only during a hands-free take. On Wayland, request a modified key through the portal or GNOME shortcut setup, preserving existing bindings and leaving plain Escape with the desktop.

### Finish a shortcut dictation (R1–R3)

- Keep 200 ms of microphone audio after the deliberate gesture that ends a take. Give a continuing word up to 600 ms total, finishing after 160 ms of quiet. A brief key click shall leave the minimum tail.
- Decide from the original microphone samples and use the same final audio for Rumble2 Flash and History. Keep the stop cue outside the recording. Workspace and explicit command stops shall remain immediate.
- Bound the wait for delayed packets and preserve cancellation before paste or History is committed. Use short Pulse packets on Linux and the WASAPI performance-counter clock on Windows.

### Recover an interrupted dictation (R1–R3)

- If a deliberate dictation loses its microphone or receives no audio for four seconds, finish the committed recording through the local speech and output pipeline. Retain the transcript and original clip according to the existing History settings.
- Clear the insertion target and copy the recovered text to the desktop clipboard. If copying fails, keep the text available through **Copy last** and **Paste Last**. An interrupted take with no recovered speech shall preserve the previous clipboard and History.
- Keep the ordinary finish, cancellation, duration limit, and microphone-only session behavior. A stale shortcut release shall leave the recovered take alone.

### Dictate while an earlier take processes (R1–R4)

- Allow the next take once the previous microphone closes. Keep up to eight pending takes and report a full queue before opening another capture. Keep Rumble2 Flash, output transformations, History, and delivery in submission order.
- Hold each take's audio, output settings, and destination until it finishes. Follow each platform's existing focus policy. On Wayland, keep older overlapping takes available for recovery when the portal cannot identify the original field.
- Start paste and completion cues after the active microphone closes. Cancel the active capture or most recent queued take before commitment. Keep in-flight paste and clipboard restoration atomic.

### Other playback during dictation (R2, R3)

- Leave playback alone by default. Offer mute and a configurable volume reduction for other apps on the default output, and pause for compatible media players on Linux and Windows.
- Restore changes on stop, cancellation, or engine exit. Keep audio from delaying transcription and preserve playback changes the user makes during the take.

### Idle sleep during capture (R2, R3)

- Request idle-sleep prevention for an intentional dictation, audio recording, or screen recording once capture begins. Keep the request independent of playback settings.
- Release the request when the recorder exits, including after cancellation or failure. Leave source selection, transcription, and export outside the request. A denied request shall leave capture available.

### Reopen the running desktop workspace (R2–R4)

- A later launch of the same library shall reopen its existing window, including when minimized, and preserve the active engine and recording. Simultaneous launch requests shall share one owner.
- Closing the desktop shall release its claim before a fresh launch. The Windows updater shall still wait for the installed launcher to exit and start the selected version through the stable launcher.

### Launch at login (R2–R4)

- Installed builds shall offer a per-user, default-off startup setting in General settings. Use the operating system registration to read and change the setting. Preserve unrelated registrations.
- A login launch shall start the owned engine without opening a window. Restore the explicitly enabled global shortcut after speech is ready. A manual launch shall open the workspace in that engine.
- The registration shall point at the stable installed launcher across updates. After the workspace opens, closing it shall stop that engine.

### Meeting recording (R1–R4)

- The desktop Meetings workspace shall start, show live speech from, and save a recording of the microphone and computer audio. Use Rumble2 Flash and Nemotron on the aligned mix and retain both original tracks. Normal recording shall continue to support independent source selection.
- A manual meeting shall capture active hardware playback routes, including a device the call app selected outside the default route. Keep recording from working routes during a device change and pick up newly available outputs. On Linux, skip virtual effects or combined sinks while hardware is available and use the default output on virtual-only systems.
- Recover an interrupted meeting with the original language and voice settings. StuPASE and microphone boost shall default off and affect only recognition for the final transcript. Preserve the original mix and tracks.
- List past meetings, support transcript copy and exports, and reuse local Qwen titles and summaries. Store meeting and audio retention in the library. Archive expired or explicitly removed meetings through the desktop Trash or Recycle Bin, keeping a local queued archive on failure.
- Offer recording for sustained microphone activity from supported apps after opt-in. Save Ask, Always record, and Never offer per app. On Windows, allow per-site policies when a supported browser exposes a known call address. Require approval when the browser call only has a matching title or has no recognized address. Let users save a recording policy from the current offer and leave the policy unchanged when they open or cancel its options. Offer desktop controls while the workspace is hidden, without taking focus. When enabled, confirmed absence of the call app from both microphone and playback on an automatic recording shall start a 30-second countdown with Keep recording. Resumed microphone or playback activity cancels the absence countdown. A confirmed Google Meet room switch can also start the countdown, which clears if the original room returns.

## Design

### Local runtime

The existing macOS build uses PyTorch MPS for speech by default. Qwen pins an Apple Silicon llama.cpp executable. The macOS bundle uses the AppKit host from Vercel Labs’ Zig-based Native SDK 0.11.1, Mach-O helpers, and native audio/capture APIs. Use the same Native SDK as the Windows and Linux host, with WebView2 on Windows and WebKitGTK 6.0 on Linux. Reuse Jaro’s React workspace and local Python engine. The host starts and owns the engine, verifies its loopback identity before loading the workspace, and exposes Jaro’s typed IPC only to the local workspace. Keep the signed macOS host in place while verifying the new ports. [Native SDK](https://github.com/vercel-labs/native) · [macOS build](../../desktop/build-tools/README.md)

The source engine defaults to CPU and float32 on Windows and Linux. Set `JARD_INFERENCE_DEVICE=cpu` on macOS to exercise the same path. This runs the pinned Rumble2 Flash and CTC weights in float32 and places Nemotron on the CPU. Use `JARD_INFERENCE_DTYPE=bfloat16` to measure Rumble2 and CTC in reduced precision. With neither variable set, macOS uses MPS and bfloat16 for Rumble2 and CTC. Start hardware acceleration with supported NVIDIA x64 configurations after measuring them. Exercise accelerator startup failures and resource exhaustion with CPU fallback or a clear error that preserves the recording. Verify Qwen separately with a native llama.cpp executable. [PyTorch platform support](https://docs.pytorch.org/get-started/additional-platforms/)

Use platform-specific CPython 3.13, PyTorch, FFmpeg and llama.cpp runtime manifests with pinned sources and hashes. The current lock includes CPython 3.13 PyTorch wheels for Linux x86-64 and Windows x64. Verify and pin a CPU-only runtime per target before measuring its installed footprint. Share the existing pinned weight catalog, licenses, and notices. The current weight assets total about 3.6 GiB across Rumble2/CTC, Nemotron, and Qwen. Download each asset when needed, resume interrupted downloads, verify size and digest before an atomic install, and test concurrent setup. Verify redistribution for each runtime asset, especially the FFmpeg build and GPU dependencies. [Model catalog](../../desktop/build-tools/models.json) · [Model notices](../../desktop/build-tools/MODEL-NOTICES.txt)

### First-run model setup

Use the verified model installer already shared with the CLI. Its manifest supplies the download size, and its events supply completed bytes. The owned engine reports model setup through its existing status endpoint and accepts the start request from its authenticated workspace origin. A single engine job owns installation and model loading. The file lock also coordinates setup with the CLI. Download failure and model startup failure have separate retry actions.

### OS integration

Keep the engine proof and token exchange for CLI and SDK connections. Use Windows Known Folders and XDG paths with current-user access controls. Port POSIX-only file locks, cleanup, and process control with their existing guarantees. Keep Qwen’s control endpoint local and protected by OS access controls or authenticated loopback. Ensure its worker can yield to recording and stop without abandoning an active capture. Use Windows Recycle Bin and desktop Trash through a platform adapter so expiration stays recoverable. [TypeScript client](../../sdk/typescript/index.mjs) · [XDG base directories](https://specifications.freedesktop.org/basedir/)

Reuse the portable workspace authentication and same-origin check for startup changes. Register the stable Windows launcher in the current user's Run key and the Debian launcher in the user's XDG autostart directory. A background launch claims the library and verifies the engine before waiting for the native window request. When a manual launch arrives, pass its startup token to the window being created. [Windows startup registration](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys) · [Desktop Application Autostart Specification](https://specifications.freedesktop.org/autostart/latest/)

Use the portable recording controller for manual meetings and write meeting intent, language, start time, and voice settings to the existing draft marker format before capture. The ordinary final save path runs mixed speaker recognition and publishes directly into Sessions. Read source microphone PCM at the capture's sample rate before optional cleanup or boost. Use GIO on Linux and a Recycle Bin operation on Windows for archived media. [GIO Trash](https://gnome.pages.gitlab.gnome.org/gtk/gio/method.File.trash.html) · [Windows File Operation flags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)

Manual meetings run one input per route and deliver the microphone and mixed computer audio to the same draft writer. Linux polls the Pulse device list, uses a bounded packet buffer per route, and places packets on a monotonic recording clock. Windows enumerates active WASAPI endpoints and uses packet timestamps on the common performance-counter clock. An unavailable route is retried independently. Preserve the selected-source path for ordinary recordings and keep the two meeting WAVs aligned for recovery. [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

The owned engine checks active, uncorked Pulse microphone streams on Linux and active WASAPI capture sessions on Windows. It maps process names to known providers and retains only observation timing and local preferences. The workspace presents a lightweight offer and recording controls. Automatic recording and stopping use the same backend capture and recovery as manual meetings. Reset the countdown if microphone observations fail or the call resumes. Use automatic language detection for unattended starts. [WASAPI session enumeration](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-getsessionenumerator)

The standalone CLI and engine no longer import `fcntl` at startup. The Python client reads its child’s readiness record on a bounded pipe wait and still checks the PID and authentication fields. The Windows helper joins a job object before launching any decoder. The Python and TypeScript clients close its stdin to request shutdown and target only their owned child if shutdown times out. Job close then ends its decoder children. Windows uses a dedicated file lock for verified model installation. The Windows CLI currently supports `model` and `transcribe`. Native validation of job shutdown, file locks, and the pipe is still required. The source engine uses the user’s local application-data directory on Windows and XDG data directory on Linux. On Windows the writing worker binds an OS-assigned loopback port, requires a per-process key for inference, and runs at below-normal priority. Long speech jobs can release an idle writing worker. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) · [llama.cpp listener and authentication](https://github.com/ggml-org/llama.cpp/blob/b12521/tools/server/server-http.cpp)

The source launcher starts the Python engine with a parent-owned pipe and proves its loopback identity. The Zig host loads the React workspace with navigation pinned to that engine’s origin. A key passed through the host’s environment and a URL fragment opens an HttpOnly browser session. Requests from another origin, an unexpected Host, or a session without the cookie cannot access the workspace. Either process exiting closes the other. File import uses the system chooser and the existing session pipeline. System dictation, native capture, updater IPC, and per-user desktop preferences require target adapters.

Claim the library with an OS-held lock before starting its engine. A later launcher queues one local window activation through the private library directory and exits. The owner forwards it over a nonblocking pipe to the Native SDK host. GTK receives the desktop's startup ID when available. Windows requests foreground permission for the running host PID. The activation channel has no engine key or API access. [GTK startup notification](https://docs.gtk.org/gtk4/method.Window.set_startup_id.html) · [Windows foreground permission](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow)

- **Windows** · The Native SDK host launches Jaro’s shared recorder with a dedicated WASAPI helper. The helper uses the default multimedia capture and playback endpoints for the duration of a take. Prove device selection, permission denial, and route changes on native Windows. Verify hold-to-dictate and global shortcut support. Use Windows Graphics Capture for screen sources and a native insertion layer. Verify focus and preserve prior clipboard contents when safe. When Windows blocks insertion into a higher-integrity app, offer Copy Last. Stage updates beside the running version and switch versions after Jaro exits. The workspace records through PipeWire’s PulseAudio service (or PulseAudio) using FFmpeg. Microphone mode excludes playback monitors. Computer-audio mode follows the monitor reported for the default playback sink. The combined mode aligns both inputs using their Pulse packet timestamps. It keeps separate mono source files on the same timeline and uses the mix for Rumble2 Flash and Nemotron. Use the ScreenCast portal for consent-based screen capture on Wayland. [FFmpeg PulseAudio input](https://ffmpeg.org/ffmpeg-devices.html#pulse) Probe GlobalShortcuts and consent-based input per desktop. Use X11-specific hotkey and input APIs on X11. [PipeWire PulseAudio service](https://docs.pipewire.org/page_man_pipewire-pulse_1.html) · [Desktop portal interfaces](https://flatpak.github.io/xdg-desktop-portal/docs/) · [Remote Desktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)
- **Both** · Preserve microphone-only recording and separate meeting source tracks. Align and mix meeting tracks for the same transcription and diarization pipeline used by sessions. Verify permission and audio-route recovery, including microphone-only operation after system audio is denied. Confirm that reminders, calendar consent, wired device capture, and agent handoffs have platform adapters or clearly identified availability.

Linux keyboard grabs and the Wayland portal feed press and release edges to the same dictation controller. Store the mode per library in a dedicated preference and change it only between takes. For a short first tap in the combined mode, keep the pending capture until the double-tap window closes, then discard it if unclaimed. Avoid reopening the microphone on the second tap.

Use separate local preferences for directly registered and portal shortcuts. After the speech model loads, the owned engine reenables the saved listener under the same lock used by the settings action. The compositor still assigns the Wayland keys. A normal quit or update releases the process-owned listener and keeps the preference.

Use the Remote Desktop portal’s version 2 persistence for the keyboard and clipboard session. Store its single-use restore token in the private per-library database, consume it before a restore attempt, and persist only the successor from a response granting both capabilities. A normal quit closes the session and preserves the successor. [Remote Desktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)

Keep portable output preferences in the existing dictation database. Share the macOS vocabulary editor and deterministic output functions. Match explicit replacements against whole phrases in one pass, preferring longer overlapping matches. If configured processing produces no text, finish without pasting or creating a history entry.

Reuse the ordered profile editor, parser, and local Qwen rewrite. Match the captured Windows application or X11 window class at take start, then snapshot the selected profile with the other output preferences. Use profile vocabulary first in the Rumble2 Flash hint. Preview deterministic text steps through the owned desktop workspace. Run the local rewrite under the profile deadline, including time spent waiting for the model, and keep processing the original text after a rewrite failure.

Run the compact dictation indicator from the owned portable engine. Send a bounded stream of level and stage frames over its lifetime pipe, with no transcripts or audio bytes. The native surface exits on pipe closure. Use a layered non-activating window on Windows, layer-shell with an empty input region on Wayland, and an override-redirect window with an empty input shape on X11. Try the existing XWayland display when a compositor has no layer-shell.

Play short WAVs through the existing default output using PulseAudio on Linux and WinMM on Windows. Scale only the cue, without changing system output volume. Stop previews and older cues before starting a new take. Keep the original audio for History and use the existing non-speech check during transcription. Hold the completion cue until a successful paste that took at least two seconds after capture stopped.

Route cancellation through the existing portable dictation controller. Close capture and clear the temporary draft before reporting completion. Saving history and delivering text share a commit point after inference. Use a temporary X11 key grab for Escape and preserve already approved Wayland portal assignments on restart. An explicit shortcut setup can add the Wayland cancel chord to older libraries.

Store playback preferences in the per-library dictation database. An optional worker owns the settings it changes and restores them when the engine closes its lifetime pipe. Linux uses PulseAudio for mute and lower and MPRIS for pause. Windows uses active WASAPI render sessions for mute and lower and WinRT media sessions for pause. Both resume the players Jaro paused only when they are still paused and their track metadata matches. [WASAPI session enumeration](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-getsessionenumerator) · [Windows media transport](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession)

Take the idle-sleep request asynchronously. The recorder's completion owns release even if the operating system responds late. On Linux, hold the descriptor returned by logind and fall back to idle-only when sleep blocking is declined. On Windows, use a system-required power request handle. The OS also closes each kind of handle if the Jaro engine exits. [logind inhibitor API](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html) · [Windows power requests](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powercreaterequest)

## Build the source shell

Build the workspace with `bun run build`. Install the pinned Python dependencies and FFmpeg, along with Native SDK CLI 0.11.1 and Zig 0.16.0. On x64 Linux, install the target distribution’s GTK4, GTK4 layer-shell, and WebKitGTK 6.0 development packages. Build on that Linux distribution so Zig links the available system WebView. The Windows x64 shell supports cross-compilation and uses the Windows system WebView2 runtime.

```text
python desktop/portable/build.py linux
python desktop/portable/open_workspace.py desktop/out/portable/linux/bin/jaro
python desktop/portable/build.py windows
python desktop/portable/open_workspace.py desktop/out/portable/windows/bin/jaro.exe
```

Run the launcher on the matching platform with the existing speech assets installed or `JARD_MODEL_DIR` pointing at a verified model directory. These source builds run the host and local workspace from a checkout. T4 covers installers and updates.

The Windows build places `jaro-capture.exe` beside `jaro.exe`. Keep both files in the same folder. The workspace offers microphone only, computer audio only, and both. Combined capture shows separate meters and keeps the aligned source WAVs alongside the mixed audio used by the speech and speaker-labeling models.

On x64 Linux and Windows, run `python engine/jardctl.py model install --all` to prepare the full model set, then use `model status --all` to check it. This installs the pinned Rumble2 Flash and alignment weights, Nemotron, Qwen, and the CPU runtime into the workspace's model directory. Downloads require curl. For offline setup, add `--from /path/to/model-set` and include the verified runtime archive under `qwen/` in that folder. Use `llama-b12521-bin-ubuntu-x64.tar.gz` for Linux and `llama-b12521-bin-win-cpu-x64.zip` for Windows. The engine finds the installed worker next to the Qwen weights. [llama.cpp b12521](https://github.com/ggml-org/llama.cpp/releases/tag/b12521)

Linux recording also needs `pactl` and an FFmpeg build with the `pulse` input device. Choose **Microphone only**, **Computer audio only**, or **Microphone + computer audio** before recording. Jaro records locally to a private WAV and reads recent PCM for the meter and live transcript. Stop saves through the normal session pipeline. Closing the host with a recording active keeps an interrupted recording available under **Recover** when Jaro reopens.

On an X11 session, open **Dictation** and select **Enable shortcut** for the current launch. With Jaro open, press **Ctrl+Alt+Shift+D** in any app to start, and press it again to finish. Jaro uses the microphone selected under **Voice input**, waits for held modifiers to be released, then sends the paste shortcut to the original focused window. Select **Ctrl+Shift+V** in Dictation for terminals that use it. Jaro remembers that paste preference. Jaro restores the previous clipboard formats if it still owns the selection, and hands them to the desktop clipboard manager on quit when one is present. If the window loses focus or Jaro cannot read the clipboard, the transcript stays available through **Copy last** for this launch. [X11 keyboard grabs](https://www.x.org/docs/X11/xlib.pdf) · [X11 selections](https://www.x.org/releases/current/doc/xorg-docs/icccm/icccm.html)

On Wayland, select **Enable shortcut** and approve the shortcut through the desktop’s Global Shortcuts portal when supported. Jaro suggests **Ctrl+Alt+Shift+D** and shows the desktop’s actual assignment. Press it once to start dictation, then again to finish. Portal version 2 also supports **Configure shortcut**. The source launcher adds a per-user Jaro desktop entry so the portal can show the application name. [Global Shortcuts portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) · [Application registration](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.host.portal.Registry.html)

On Wayland desktops that use command bindings, open **Dictation → Enable commands** and copy **Toggle dictation** to a custom shortcut in your desktop’s keyboard settings. Use **Start dictation** and **Finish dictation** on the press and release of the same key for hold-to-dictate. For Sway, use `bindsym --no-repeat` for a press and `bindsym --release` for a release. Put the full copied command in double quotes after `exec` when its paths include spaces. Commands reach the running workspace for the library shown in the copied command. The choice stays enabled when that workspace reopens. [Sway keyboard bindings](https://github.com/swaywm/sway/blob/master/sway/sway.5.scd)

Select **Allow paste** for automatic insertion. This asks for keyboard and clipboard access for the current session. Finish dictation with the shortcut while keeping focus in the field where the text should go. Jaro restores the previous clipboard if it still owns the selection and leaves any newer copy alone. Both **Ctrl+V** and **Ctrl+Shift+V** are available. If a portal or clipboard operation is unavailable, the result stays available through **Copy last** and History. **Start dictation** and **Finish dictation** are also available in Jaro when the desktop lacks global shortcuts. Both paths use Rumble2 Flash and the same history. [Remote Desktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html) · [Clipboard portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Clipboard.html)

Open **Dictation → History** to search saved text or the destination app name, see audio duration and processing time, copy results, or delete selected entries. History stores text and metadata in a private local database and defaults to seven days. Choose one or thirty days, or turn History off to stop saving new entries. Existing entries continue to expire under the last selected retention period. Jaro removes the temporary audio after transcription. From the source checkout, use `python engine/jardctl.py history --search "notebook" --json` to search with the app closed, or `python engine/jardctl.py history clear --yes` to clear the retained entries. [SQLite deletion settings](https://www.sqlite.org/pragma.html#pragma_secure_delete)
